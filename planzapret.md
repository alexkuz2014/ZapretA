# ЦЕЛЬ
Сделать «ZapretA» — один portable .exe на Rust для Windows 10/11 x64.
Сценарий пользователя:
1. Дважды кликает .exe → UAC (манифест requireAdministrator).
2. Программа сама: определяет, что именно блокируется → подбирает рабочую стратегию обхода → тестирует её → применяет → открывает YouTube.
3. Висит в трее, следит за работоспособностью и при деградации переподбирает стратегию сама.
Никаких .bat, ручного выбора general (ALT), ручной настройки ipset/hostlist и установки зависимостей.

# ЭТАП 1 — ЯДРО (после апрува)
Структура: Cargo workspace.
- `core` — модели, каталог стратегий, парсер/генератор аргументов winws, скоринг.
- `engine` — запуск/остановка winws (встроенный, распаковка в %LOCALAPPDATA%, проверка SHA-256), жизненный цикл WinDivert, гарантированный cleanup (kill дочерних процессов, выгрузка драйвера при выходе/панике/Ctrl+C).
- `probe` — тестирование доступности.
- `net` — DoH-резолвер, загрузка списков, зеркала с fallback.
- `app` — точка входа, трей, минимальный UI (egui или нативное окно) + CLI (`--auto`, `--strategy`, `--diagnose`, `--no-browser`, `--log`).
Стек (обоснуй отклонения): tokio, reqwest(rustls), tokio-rustls, hickory-resolver (DoH), serde/toml, clap, tracing, sha2, tray-icon, crate `windows`, embed-resource (манифест admin), rust-embed/include_bytes.
Сборка: single static exe, `panic = abort` только если cleanup через отдельный watchdog; LTO, strip.

# ЭТАП 2 — АВТОПОДБОР (главная ценность)
Алгоритм `probe`:
1. Диагностика без обхода (baseline): DNS (системный vs DoH — отличаются ли ответы, подмена), TCP:443 connect, TLS handshake с SNI youtube.com / googlevideo.com / ytimg.com / discord.com, QUIC/UDP 443, реальная загрузка небольшого чанка видео-CDN с замером скорости (блокировка часто = обрыв/throttling после первых КБ, а не отказ в connect).
2. Классификация типа блокировки (DNS-подмена, RST по SNI, дроп ClientHello, QUIC-блок, throttling) → приоритизация стратегий из каталога под этот тип.
3. Перебор стратегий последовательно (одновременный запуск нескольких winws запрещён — конфликт перехвата): запуск → прогрев → тест-набор → оценка (успешность, скорость, стабильность) → остановка → следующая. Таймауты и ранний выход при провале первого же критичного теста.
4. Победитель: повторная валидация, затем кэш в `%LOCALAPPDATA%\ZapretA\state.toml` (ключ — ASN/провайдер + хеш каталога). При следующем запуске — fast path: проверить кэш за <5 сек, только при провале полный перебор.
5. После успеха: открыть https://www.youtube.com в браузере по умолчанию, показать в трее статус.
6. Watchdog: каждые N минут лёгкая проверка; при деградации — тихий переподбор, уведомление в трее.
7. Защита от ложноположительных: тест с контрольным заведомо открытым сайтом, чтобы не засчитать «работает» при проблемах самой сети.
