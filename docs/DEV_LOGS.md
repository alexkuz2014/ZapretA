# DEV-сборка: подробные логи

DEV-сборка — тот же `ZapretA.exe`, собранный с `--features devlog`. Работает так же, как обычная, но пишет на диск всё, что нужно, чтобы по логам понять, что происходило на конкретной сети. **Ничего никуда не отправляется**: файлы лежат локально, пользователь сам решает, что прислать.

Скачать: артефакт `ZapretA-DEV-windows-x64` в запуске Windows CI (`ZapretA-DEV.exe` + `SHA256SUMS-DEV.txt`). В релизы DEV-сборка не попадает.

## Как пользоваться

1. Запустить `ZapretA-DEV.exe`, подтвердить UAC, нажать «Включить».
2. Во вкладке «Сайты» добавить сайты, которые не открываются, и пользоваться компьютером как обычно, лучше 15–30 минут (чтобы отработал сторожевой таймер).
3. Вкладка «Журнал» → **«Собрать архив для отправки»**. Откроется папка с `ZapretA-devlogs-<дата>.zip`.
4. Прислать архив и дописать: провайдер, город, проводной интернет или Wi-Fi/мобильный, какие именно сайты не открывались.

Папка логов: `%LOCALAPPDATA%\ZapretA\devlogs` (кнопка «Открыть папку логов»). Хранятся последние 8 запусков, более старые удаляются при старте.

## Что записывается

| Файл | Содержимое |
|---|---|
| `session_<дата>.jsonl` | Все события, по одному JSON в строке. Основной источник. |
| `summary_<дата>.txt` | То же, что вкладка «Журнал», с временем. Удобно читать глазами. |
| `system_<дата>.txt` | Версия Windows, сетевые адаптеры (имя, статус; без MAC и IP), DNS-серверы, настройки DoH, TCP, системный прокси, установленный антивирус, Secure Boot и HVCI, службы WinDivert/GoodbyeDPI, **имена запущенных процессов**. Можно не отправлять. |
| `engine_<дата>_<n>-<стратегия>.log` | Собственный отладочный лог `winws` (`--debug=@файл`): хосты соединений и выбранный профиль. |
| `engine_<дата>_<n>-<стратегия>.out.txt` | Что движок написал в stdout/stderr: ошибки запуска, отказ драйвера WinDivert. |

Если журнал движка у работающей стратегии вырастает больше 40 МБ, движок перезапускается с новым файлом (это краткий разрыв обхода).

Чувствительное: в логах видны имена сайтов, которые вы открывали (кэш DNS Windows и лог движка), список запущенных программ и ответы DNS для ваших сайтов. Если что-то не хотите отправлять, удалите соответствующий файл из архива.

## События `session_*.jsonl`

У каждой строки есть `t` (UTC), `ms` (от старта) и `kind`.

| kind | Поля |
|---|---|
| `session_start` | версия, ОС, аргументы |
| `goals` | цели подбора, сайты/IP/исключения пользователя, настройки |
| `dns` | `name`, ответы системного DNS и DoH (адреса, состояния, ошибки) |
| `search_start`, `search_report`, `winner` | цели, базовый замер без обхода, вердикт по каждой стратегии, итог |
| `probe` | каждая проверка: `strategy` (null = без обхода), `group`, `host`, `path`, `passed`, `status`, `elapsed_ms`, `bytes`, `kbps`, `error` с цепочкой причин (`[timeout]`, `[connect]`, сброс соединения, сертификат) |
| `engine_start`, `engine_started`, `engine_start_failed`, `engine_exited_early`, `engine_output`, `engine_stop` | полный argv, PID, хвост вывода движка |
| `watchdog_control`, `watchdog` | раунды проверки работающей стратегии |
| `dns_cache_new` | новые имена в кэше DNS Windows с прошлого раунда |
| `phase`, `command`, `log`, `candidates`, `engine_prepared`, `system_info` | состояние приложения |
| `panic` | сообщение и стек при аварии |

## Разбор логов

```bash
python3 -I tools/analyze_devlog.py <папка | ZapretA-devlogs-*.zip | session_*.jsonl>
```

## Ограничения

- DEV-сборка включает у `winws` `--debug`, это может немного замедлять обработку пакетов. Для обычного использования берите обычную сборку.
- Кэш DNS Windows не содержит сайтов, которые браузер резолвит через собственный DoH; такие сайты видны только в логе движка.
- Лог движка показывает хосты только для трафика, который перехватывает выбранная стратегия (порты 80/443).
